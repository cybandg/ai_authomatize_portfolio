Redmine → Zulip: задача живёт там, где её обсуждают

Команда обсуждает задачи в корпоративном мессенджере, но данные лежат в Redmine. Раньше это означало сырую ссылку → медленный веб-интерфейс → потерянный тред обсуждения. Интеграция рисует задачу карточкой прямо в чате: тап — и bottom sheet с полным описанием, исполнителем, вложениями и комментариями появляется за доли секунды, не покидая тред.

    Задача #285664

    Оркестр МП. Планшет. Сводки. Фильтр периода сбрасывается после поворота экрана

    ✅ Решена 🚩 Срочный Mobile-bug
    👤 Исполнитель: Андрей Елфимов 🧑💼 Владелец: Павел Стрельцов
    Описание

    Раздел «Сводки», вкладка «По кварталам». При повороте планшета фильтр периода сбрасывается на «год» и данные пересчитываются неверно. Воспроизводится на Android 14+ (см. вложение).

    🎯 Контекст

    • Обсуждения задач велись в Zulip, данные — в Redmine
    • Каждая ссылка = загрузка веб-интерфейса, авторизация, потеря треда
    • Статусы задач в чате устаревали мгновенно

    🛠 Решение

    • Сервис-интегратор слушает события Redmine (REST + webhooks)
    • Бот Zulip рисует/обновляет карточку задачи прямо в треде
    • Flutter-клиент: тап по карточке открывает bottom sheet с деталями (статусы, исполнитель, вложения, комментарии)

    📈 Эффект

    • Данные задачи — за 0.4 c вместо минут на переходы
    • Обсуждение и контекст задачи живут в одном треде
    • Статусы в чате всегда актуальны: карточку обновляет бот
    Мокапы чата и карточек стилизованы под реальные интерфейсы, но не копируют их точь-в-точь; имена, проекты и номера задач синтетические. Реальные скриншоты решения — по запросу.
